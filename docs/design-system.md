# Desktop design and interaction conventions

This documents shared UI conventions and the current implementation. Proposed refinements and implementation gaps are explicitly marked.

## Reference and layout

The shell was implemented after reading SiYuan v3.8.5's layout, tabs, docks, list styling, default themes and Electron titlebar code. It is an independent implementation. Reference: [SiYuan source at v3.8.5](https://github.com/siyuan-note/siyuan/tree/v3.8.5/app). Explorer context actions also follow the compact, contextual approach in [VS Code's context-menu guidelines](https://code.visualstudio.com/api/ux-guidelines/context-menus).

`src/renderer/styles.css` is the source of the visual tokens. The default font stack begins with `BlinkMacSystemFont, Helvetica` and uses system emoji fonts. Default UI text is 14px. The merged title/tab row and Action Ribbon are 42px. Left/Right Side Docks initially measure 232px/280px; Tab Group tab strips are 34px. The statusbar is 32px. List rows have a 28px minimum height and 1px/8px outer spacing. Panel corners are 12px, control corners 6px. Controls use restrained hover fills and visible keyboard focus, not decorative cards or large instructional copy.

The **Main Dock** is the central region containing Whiteboard View, Card View and other content views. It can split horizontally and vertically. Left and Right Side Docks flank it. See [UI terminology](ui-terminology.md) for the agreed names and their existing implementation identifiers.

Light and dark palettes are CSS variables. A workspace's theme can follow the system. Tabs are unique within one Main Dock Tab Group; the same document can be open in different Tab Groups. Each group keeps its own view position while editing the same underlying file. The mother whiteboard uses the workspace folder name and contains sub-whiteboards. Existing root cards remain accessible for explicit migration.

## Scrollbars

Scrollbars show only the draggable thumb; the track stays transparent, without a separate background or border. Apply this to both axes throughout the app: Explorers, Starred and Recent, cards/editors, History, tag views, menus, dialogs and embedded widgets.

Use the shared native CSS rules in `styles.css`: thin scrollbars with `scrollbar-color: var(--scrollbar-thumb) transparent`. The thumb token blends the theme's muted color at 65% opacity so it works on light and dark surfaces. Scrollbar color inherits into embedded widgets, including the emoji picker. Existing hidden Tab Strip and Action Ribbon scrollbars remain hidden.

Keep native scrolling, thumb dragging, keyboard navigation and system visibility behavior. Do not add custom scrollbar elements, track decorations, scroll listeners or hover-triggered width changes. Forced-colors mode uses system scrollbar colors for accessibility. New scrollable Views inherit this convention instead of defining their own track fills.

## Settings switches

Every binary on/off setting uses a pill-shaped toggle switch, with its label on the left and the switch aligned to the right. Off places the circular thumb on the left of a neutral track; On moves it right and fills the track with the theme accent. Keep the label unchanged between states. The shared control is 36 × 22px with a 16px thumb in a row at least 32px tall. Use the theme tokens `--switch-off`, `--switch-on` and `--switch-thumb`; color and thumb motion follow the shared motion tokens and reduced-motion preference.

Use a native `<input type="checkbox" role="switch">` inside a `.settings-toggle` label. Clicking either the label or switch changes the setting; Tab focuses it and Space toggles it. Keep a visible keyboard focus ring, native checked/disabled semantics and system colors in forced-colors mode. Disable it while saving, keep the last saved state on failure, and show the error. Help and restart notices sit below the row; a restart-required setting shows the saved choice while diagnostics report the running state.

This convention applies to on/off preferences in Settings and Views, including **Hardware acceleration** and **Show mention links** in Style View. Document task checkboxes and checked context-menu commands retain their own semantics; multi-choice settings retain their appropriate controls.

## Docks and navigation

Use the names in [UI terminology](ui-terminology.md). The Left and Right Side Docks have the same layout and controls: vertically resizable Tab Groups, a tab strip for each group and a tab context menu for close/move/split/merge commands. Right-click an individual tab to act on that View; right-click unused Tab Strip space to act on the active View. Shift+F10 or the Menu key opens the focused tab’s menu. There is no persistent **…** button. View controls sit inside the active group's content. The Action Ribbon contains actions for revealing the current Side Dock Views and opening Settings. A View action reveals it in its assigned group and expands that dock. The window toolbar collapses either dock independently. **Close View Tab** closes the selected tab without deleting content; the Action Ribbon reopens a closed Side Dock View in its remembered group, recreating that group if needed. Closing the last tab removes its Side Dock group; closing the last group collapses that dock. Closed placements persist with the Workspace layout. Main Dock tab context menus also provide **Close View Tab**, using the same save behavior as their existing close button.

The bottom-left **workspace switcher** uses Lucide's `ChevronsUpDown` icon, aligned with the Action Ribbon's icons, followed by the folder name. Its menu opens upward and contains registered workspace names with the current one checked, then a divider and **Manage workspaces** with the Database icon. Paths appear in tooltips. Manage workspaces shows each full path, availability (**Available**, **Folder not found**, **Cannot access**, or **Not a folder**) and **Last updated**. Unavailable rows remain visible but cannot be opened; unregistering removes only their registration. Refresh checks the filesystem again. Last updated means the newest file/folder modification, including workspace settings, excluding Git internals and linked folders. Retain the last known time when unavailable; use **Unknown** when none was recorded. The manager is also accessible from the welcome screen without an open workspace. Sync and save/checkpoint state occupy the right end of the status bar. Word/card counts and undo/redo buttons are absent there.

- **Whiteboard explorer** is the daily navigation View: actual whiteboards, cards and tag pages. Ordinary folders and assets stay out. The disclosure arrow expands a whiteboard; clicking its label opens it.
- **File explorer** is a separate View. Folders expand on click. It shows Markdown, `.whiteboard`, `.tag`, attachments, hidden files and app/Git internals. Listing never changes a folder into a whiteboard. Refresh is explicit for ignored/internal directories that the workspace watcher does not monitor.
- A row's **+** and **…** appear on hover or keyboard focus; on touch they remain visible. **+** on a folder offers only **New whiteboard** and **New note**. The root's note action is disabled with an explanation in its tooltip.
- An item’s right-click menu and hover **…** call the same action builder: open, open to side, bookmark, icon, source inspection, path copy and reveal. Explorer-wide Refresh and Collapse folders live in its background context menu. Shift+F10 or the Menu key opens the focused item/background menu; menus support arrows, Home/End and Escape, and restore focus when closed. Explorer has no standalone **…** button or empty toolbar row. Search retains its input and clear action. Unimplemented rename/delete/move actions are omitted.
- Starred and Recent share one scrolling panel. Empty Starred occupies only its header, which accepts drops. Document icons stay visible on hover/drag; there is no section drop highlight. Recent stays chronological. Starred is manually ordered. Dragging changes bookmarks, never file locations. The precise drag behavior is in [drag-and-drop.md](interactions/drag-and-drop.md).

## Side Dock tabs and motion

Side Docks and the Main Dock share the View/Tab Group model but have distinct tab styling. Main Dock tabs retain their existing appearance. In each Side Dock Tab Group, the active tab shows its icon and View name on the same surface as its content, with no gap or border between them. The Tab Strip has no trailing menu padding: a sole or rightmost active tab reaches the content’s right edge. Inactive tabs show icons only. Names truncate when space is tight; tooltips and accessible names retain the full title. Tabs keep their order when selected, and overflow scrolls horizontally, keeping the selected tab visible after it expands. The View name is not repeated in a content heading; View-specific tools remain inside the content.

Motion uses CSS tokens in `styles.css`:

| Token | Default | Use |
| --- | --- | --- |
| `--motion-fast` | 120 ms | Hover, focus, color and opacity feedback. |
| `--motion-normal` | 180 ms | Small state changes, including active Side Dock tab expansion. |
| `--motion-ease` | `cubic-bezier(.2,0,0,1)` | Ease out without bounce or overshoot. |

Keep motion local: Side Dock tab widths and labels transition, while content switches immediately without sliding or fading the whole View. Prefer transform/opacity for other motion; the short tab row is the deliberate size-animation exception. Avoid `transition: all`. Dragging, resizing and whiteboard navigation must track the pointer without easing; Side Dock phantoms expand and other tabs collapse using the same width and label timing as ordinary selection. Only size and appearance ease; phantom X/Y follow the pointer immediately. Bookmark and tab neighbors share the same 150 ms displacement animation. See [shared drag-and-drop interactions](interactions/drag-and-drop.md) for source fallback, empty destination slots, empty groups and dock-family restrictions. Reduced motion sets these durations to zero. The existing 650 ms Main Dock focus indicator remains a separate attention cue and is disabled under reduced motion. New animations should use these conventions rather than add arbitrary timings or a motion library.

## Breadcrumbs and navigation

The document toolbar uses a compact workspace-relative breadcrumb trail. Ancestor whiteboards are clickable, separated by quiet slashes; ordinary folders are plain labels. The current item pairs its icon with an editable filename or whiteboard name. Parent labels truncate first when space is limited. Click an ancestor to navigate in the same tab; right-click or Shift+F10 offers **Open in new tab** through the shared menu. The mother whiteboard name is read-only.

Double-clicking a whiteboard tile also navigates in the same tab. Its menu offers **Open whiteboard**, **Open in new tab** (current Tab Group), and **Open in another Tab Group** (reuse another group or create a split). These last two commands also appear in Explorer and breadcrumb menus. New splits open to the right by default, configurable to below. Each group keeps independent view state. See [whiteboard navigation](whiteboards.md#breadcrumb-navigation-and-whiteboard-renaming) for rename and storage behavior.

## Editing in place

Selecting, focusing, editing, saving, deselecting and selecting again must preserve the same text geometry: font family, size, weight, line height, wrapping, padding and position. Editing may add a caret or a focus outline that does not affect layout. Only an actual content change may resize an auto-height card or its text. New empty cards start with a blank body line below the title. Existing cards render only their content: preserve explicit blank paragraphs, but never enforce or recreate a final paragraph after a title, list, table or other block. A deleted body line must stay deleted through focus, saving and reopening. Match preview and editor line height and paragraph spacing so activation and deactivation never change the card height. Collapsed cards remain title-only. Do not animate or enlarge content merely because editing starts.

Card preview and editor share prose spacing, including compact list paragraphs and matching checkbox/text layout. Nested lists keep the same indentation and item positions. Edge label drafts render on the curve as they are typed, using the saved label size and the same width, wrapping and anchor as the display state. Enter or blur commits once; Escape restores the saved label. Opening and closing an unchanged label makes no history entry.

Filename edits in both the card hover row and breadcrumb use the same text metrics and padding as display. The input follows the stem's text width; the read-only extension immediately follows it with no added gap or dimming. Long names stay within the available width. Focus does not select all text automatically. Rename validation and Escape cancellation remain available.

## Whiteboard cards

Expanded cards have no permanent top bar. A floating row above the card shows its editable filename on the left and the three-dot **Card actions** menu on the right. Reveal the row on hover, selection, editing or keyboard focus, and retain it while its menu is open. It occupies no content height; the formatting toolbar sits above it. Whiteboard tiles use the same menu position. Cards offer the checked **Auto height** option; whiteboard tiles offer **Open whiteboard**. The collapse chevron sits alone inside the upper-right corner, inset 7px from both edges, and stays at the same position in both states. Use a down chevron for **Expand card**, and an up chevron for **Collapse card**, indicating the action. Reserve space beside the title so text cannot overlap the button. Collapsed cards retain the same H1 font, formatting, padding and wrapping. Their minimum height is 70px and grows to fit the title. They render only indexed heading metadata, with no body reads or editors. The filename owns the full-path tooltip; the card body has none. Expanded fixed/fallback dimensions and coordinates remain saved. Cards default to natural content height with a 120px expanded minimum; manual corner resize selects fixed height. Collapse and height mode are independent. Collapse belongs to a placement, so references on other boards can have different states. See [whiteboards.md](whiteboards.md) for automatic column placement and storage.

Cards and whiteboard tiles share the bottom-right L-shaped resize control. Keep the hit target 20px square with a 9px corner mark; this is a geometric handle, not a diagonal arrow. Drag cards by their preview or 10px outer padding/frame. A preview press does not mount an editor: only release without exceeding the 3px movement threshold activates in-place editing. Movement is remembered through release, so dragging back to the start is not mistaken for a click. Once editing, content drags select text normally; the thin empty top strip and frame remain draggable. Use a text cursor over editable content, pointer over links and buttons, grab over the strip/frame and grabbing throughout a drag. Whiteboard tiles drag by their body and open by double-click or their action menu. Keep selected items above ordinary items, the active editor above those, and moving/resizing items above all three. Selection/editor layers are temporary interaction state. Completed moves also save the dropped placements at the end of the board’s ordered card list, so they remain in front after deselection and reload.

Only selected card content scrolls. Unselected previews clip their content and route the wheel to the canvas. Pinch and Ctrl/Command-wheel always zoom. Expanded previews keep the same formatted content at all zoom levels; use offscreen culling, cached HTML and lazy images instead of substituting title-only cards. The zoom percentage is a **Zoom to fit** button, between minus and plus.

A whiteboard tile uses an inline icon/name header with counts underneath, followed by a grid of miniature cards. Following the Heptabase reference, these use fixed 88 × 34 dimensions, a quiet neutral fill, 10px corners, 10px single-line text with ellipsis, and 12px horizontal/8px vertical gaps. Ordinary card previews have no icon; nested whiteboards retain a small map icon. Rows clip within the tile’s 24px inset without a scrollbar or “more” chip; resizing reveals additional titles. The open-whiteboard action appears on hover/focus/selection. Keep the 90px header and grid dimensions aligned with the renderer’s visible-item budget. It reads existing workspace metadata, never mounts recursive canvases or loads child note bodies. App actions say **New whiteboard** and **Open whiteboard**, regardless of nesting.

Every card reserves its **leading H1** as its title. If no leading H1 exists, previews and the editor show an empty heading with the gray **A new card** prompt. The prompt is a CSS overlay, not text to select/delete, not the filename, and not stored note content. Workspace settings expose **Empty card title** to customize it. Typing inserts a real H1; Enter continues into body content. Opening or focusing an empty/heading-less card does not write a file. Later H1s remain body sections, and existing body content stays in place.

## Icons and emoji

Use `Icon` and `Tool` from `Icons.tsx`; do not draw SVG paths for standard controls. Icons come from named, tree-shakable [Lucide React](https://lucide.dev/guide/react) imports, normally 16px with a 1.65 stroke. Default whiteboard/card glyphs are Map/FileText. Add a named import and mapping when a feature needs another standard glyph.

Document icons render through `DocumentIcon`. Settings store either native Unicode emoji or a known `icon:<name>` key. Empty values restore the type's default. The picker offers a curated Lucide palette and the searchable [Emoji Mart](https://github.com/missive/emoji-mart) catalog. Emoji Mart and its data load in a separate chunk only when requested; no remote sprites or emoji-data fetches are needed. Native glyph appearance varies by operating system.

## Tooltips and accessibility

All authored wording comes from the two [UI text catalogs](ui-text.md), except the deferred Settings copy.

Use `<Tool icon="…" label={tooltips.common.newCard} />` for icon buttons. For other controls, reference the tooltip catalog through `data-tooltip={tooltips.…}` and provide an accessible name when visible text is insufficient. Avoid native `title` tooltips in app components: the shared `TooltipHost` owns the overlay.

The target behavior is a tooltip after 450ms of genuine pointer hover only. Clicking, right-clicking, menu opening, keyboard focus, and programmatic focus must not show one. Opening a menu clears existing and pending tooltips; fully visible menu labels are not repeated in tooltips. Tips anchor to their owner and stay outside actionable menu rows. Accessible names and essential descriptions remain available without hover. See [Menus and tooltips](interactions/menus-and-tooltips.md) for positioning, suppression, dismissal, and the current implementation gaps.

Menus keep action names visible and close on Escape or pointer-down anywhere outside. Dropdowns and context menus share the same interaction contract; form popovers retain normal input behavior. Outside-click dismissal must not steal focus from the clicked control. Icon-only controls need an accessible name. Hover actions remain keyboard reachable. Motion honors reduced-motion preferences. Shared interaction code and these docs must change together when behavior changes.

## Edges and selection styles

Use **Edge** for editable, manually drawn curves and **Mention link** for passive indexed note references. Anchor dots and endpoint handles share one appearance on cards and whiteboard tiles. Style controls belong to the movable **Style View**, with mixed selections grouped into independently scoped sections. See [edges, mentions and Style View](interactions/edges-and-style.md) for the interaction, terminology and persistence rules.

Style controls use compact, direct button groups with visual samples for stroke thickness and dash patterns, with two independent direction buttons for arrows. In the Edges section, put Arrows directly below Color, followed by Arrowhead style (open, filled triangle, outlined triangle). Default stroke widths are 1, 2 and 4 px; preserve other saved values. All choices are presets intended for future workspace customization, not immutable file-format limits. Avoid dropdowns when the choices fit in a short row. Preserve pressed states, hover tooltips and keyboard focus. Mixed values leave choices unpressed without a “Mixed” label. Color swatches show the literal palette color at full opacity so small controls remain easy to recognize. Large card/tile fills and edge strokes use theme blending. The workspace palette is editable in Style View; edits affect future selections only. Card fill follows the source card everywhere; card and whiteboard tile borders come from the theme. Detailed stroke controls belong only to edges. Card/tile fill and edge stroke have separate sections and Color controls, headed with the type and selected count using a centered dot (for example, **Cards · 2 selected**, **Edges · 3 selected**). Both sections stay available for mixed selections. Selection does not show a floating action toolbar. See the [color and palette contract](interactions/edges-and-style.md#card-color-and-workspace-palette).


## Whiteboard grid and theme-owned appearance

The grid is automatic: small minor dots sit 24 canvas units apart, with a major dot every fifth interval (120 units). Both grids share the same world origin and pan/zoom transform. Minor dots fade from fully visible at 80% zoom to hidden at 55%; major dots remain visible throughout the supported zoom range. Dots keep a steady screen-space radius as their spacing scales. Navigation updates three camera CSS variables once per frame; two CSS background layers draw the grid without generating dot elements or rerendering cards.

There are no grid style settings. Theme CSS can override these tokens:

| Tokens | Default / purpose |
| --- | --- |
| `--grid-spacing`, `--grid-major-every` | `24px`, `5`; world spacing and major interval |
| `--grid-minor-radius`, `--grid-major-radius` | `.7px`, `1.1px`; screen-space dot radii |
| `--grid-minor-color`, `--grid-major-color` | Theme-derived quiet and stronger dots |
| `--grid-minor-hide-below`, `--grid-minor-show-above` | `.55`, `.8`; zoom fade range, with upper value greater than lower |
| `--canvas` | Canvas background |
| `--card-border-width`, `--card-border-style`, `--card-border-color` | `1px`, `solid`, theme border |
| `--card-radius`, `--card-shadow` | `6px`, subtle shadow; applies to cards and whiteboard tiles |
| `--mention-color`, `--mention-width`, `--mention-opacity` | Muted theme foreground, `1.5`, `.45`; passive mention links |

`--board-zoom`, `--grid-x` and `--grid-y` are live camera values, not theme settings or saved style fields. Major dots render above minor dots and align at every shared intersection. Selection/focus continues to use the app's accent outline. Existing saved decoration fields are preserved for compatibility but do not override the theme.

## Search and History Views

Search uses one results component in the Side Dock and keyboard dialog. Show filename with a quiet extension, relative path and a readable original-text excerpt. Highlight matched text with dedicated `--match-bg` and `--match-text` colors that remain legible on selected rows. When a card includes a local image, show one small lazy-loaded preview beneath the excerpt; the result represents the containing card. Keep the footer to result status and three compact action buttons: Show on whiteboard, Open card, Open card beside. Put shortcuts in their tooltips. Use theme colors, not a copied reference screenshot palette. Default search covers readable content and filenames, excluding storage details such as geometry, internal IDs and markup attributes. Property queries remain explicit. Arrow keys change the highlighted result; Enter/click reveals it on its whiteboard, selected and expanded at the existing zoom. Shift+Enter opens the card; Cmd/Ctrl+Enter opens it beside. IME composition must not activate results. Escape/outside click dismiss the dialog and restore focus. A newer query invalidates older responses.

History checkpoints are compact cards with ancestry lines. Current checkpoint and selected card have distinct borders/backgrounds. Single-click inspects; double-click/context menu confirms before navigation. Use the shared pointer phantom for dragging a checkpoint to another branch: preserve the original node because application copies its delta. Highlight only an eligible destination; Escape cancels. The warning names both checkpoints. Keep tabs/layout during content navigation. See [Search and History](search-and-history.md).

## Loading feedback

Render the shell before workspace opening/indexing completes. During startup or a workspace switch, show an indeterminate spinner with “Opening workspace…” and a short preparation message; keep workspace controls inert until ready. Errors leave recovery controls available. Never invent a percentage or show a normal empty state while still loading.

Search announces its busy status immediately and shows a central spinner if the request lasts 250 ms, avoiding a spinner flash on fast queries. Slow results must not look like “No matching cards.” Spinner rotation has an 800 ms loop; reduced motion leaves a static indicator and the text. Search results, menus and editor content do not animate while data loads.

## Confirmations and semantic colors

Use the shared themed native-modal dialog for potentially destructive operations and workspace history changes. Name the action and its consequence, provide Cancel and a specific action button, and focus Cancel initially. Escape or a backdrop click cancels, focus stays within the dialog and returns to the trigger on close. App/canvas shortcuts do not act on the workspace behind it. Empty-card deletion still proceeds directly; deleting meaningful content asks first and remains undoable.

Use `--positive` for additions and `--negative` for removals/destructive actions, and `--warning` for caution icons. History counts retain +/− signs so color is supplementary. Selection uses the theme accent; search matches have a separate high-contrast highlight. Avoid adding color to ordinary navigation labels.

Whiteboard explorer omits `.md` rows; File explorer shows actual files. Cards remain on the whiteboard. Direct child notes missing from the saved layout enter its persistent side column, collapsed, at a shared x-coordinate and successive y-positions. Do not rearrange already placed cards.

History uses the Git branch icon. Checkpoint cards align with commit dots in straight ancestry lanes; short bends join the shared parent lane at staggered heights along the child-to-parent span. Keep the path continuous to the actual parent, and release the old lane after its bend so later checkpoints can reuse it. Distinct branch colors stay visible above each join. Ten theme-controlled colors rotate between branches. Commit color identities are stored in the rebuildable local SQLite cache and follow their ancestry, independently of lane position or the active checkpoint; switching branches, loading earlier history and reopening the app preserve assigned colors. A rebuilt cache may assign a fresh palette order. Hashes remain neutral. The current checkpoint has an extra ring, and +/- line counts retain separate positive/negative colors. A parent beyond the loaded history continues to the bottom edge rather than appearing as a root.


## Tags

Tags appear below the H1 as one tag icon, colored `#tag` pills and a borderless input. Only one properties panel opens at a time; the active pill toggles it closed and the leading icon restores the last-used tag. Pills have no chevron. The active pill has an accent outline, stronger label and an inline More button; inactive pills stay compact. The panel has only thin top/bottom dividers, no duplicate tag-name heading or More button, and Add property at the bottom. Its menu offers absent defined properties and their defaults above a divider, then standard new property types below. A new card property registers as optional; it never adds fields to other cards. Right-click remains available; clicking a pill with its menu open only dismisses the menu. Dropping a reordered pill opens its properties, while cancelling preserves selection. Tag colors are workspace-wide Settings values. The borderless tag input fills the remaining row width with a 100px minimum; this applies to card and parent-tag rows. Suggestions appear after typing, with keyboard navigation and an explicit Create action. Tag pills reorder horizontally with the shared phantom; their frontmatter array stores order. Property labels reorder with the shared vertical phantom and placeholder; field values use the same typography and geometry while editing. Card previews and editors show the same metadata block; it never enters Markdown. Kanban uses quiet column headers, compact cards titled from H1 with filename fallback, and at most two property summaries. Stretch its columns to the same height and retain 200px (about two compact cards) of empty drop space below the longest column. Status pills use a small colored dot and a soft tinted fill: neutral for Todo, blue/accent for In progress, and green for Done. Apply the same group colors to card properties, option pickers, table cells, Kanban headers and card summaries. Option names remain visible; colors follow the three progress groups, not option order, and themes can override the status tokens. Tag removal uses the shared warning and one undoable action. Table/List/Kanban are presentations of existing cards; Kanban uses the shared drag phantom and an equivalent More-menu move action. Boolean property values use native checkboxes; switches are reserved for settings. See [Tags](tags.md).

Use seven property types: Text, Number, Checkbox, Date, Select, Status and Reference. Keep each property on one 34px row. Name and simple value inputs share their display geometry; no separate key/label form or automatic select-all. Click the name to rename, the type icon for settings, or drag the label to reorder. Date and choice summaries stay on that row; their details open in an anchored popup. Status options appear under three progress groups; Select has an Allow multiple selections setting. Date popups follow the compact calendar pattern: date and optional time on one input row (a second row for a range), month navigation, Today/Now, a seven-column calendar, End date, Date format, Include time, Time format and Timezone controls, then Clear. Keep the calendar height stable across months, mute adjacent-month days, highlight selected endpoints with the accent and the intervening range with a light tint. Use existing switches for range/time settings, quiet right-aligned format menus, and theme colors throughout. No reminder controls or Save footer. Escape cancels the value draft; valid date drafts save on Enter in an input or outside click. Display format/timezone choices are workspace preferences and never change stored note values. Dates use the same popup in card properties, table cells and tag defaults. Errors float below the affected field without increasing row height.


A tag page uses the card's property row and input components directly: a colored `#tag` pill at the standard title size, an Inherits row with a bent-right arrow, Properties, Default, Optional, Color, then Views. The title pill previews the shared tag color; the page keeps its neutral background. Inherits is indented 24px and uses the card-tag pill styles, horizontal drag and shared fuzzy input; parents open their definition on click and expose removal on right-click. Default, Optional and Color labels align with Properties at the left, with a thin divider extending to their right, matching quiet type and spacing, and no box borders. Properties has Add property and an up/down collapse button at the right. Collapse hides Default, Optional, Color and Add property, preserves inline new-property drafts and closes floating settings, and leaves Views visible. Store this state as `propertiesCollapsed` in the `.tag` file (absent means expanded). Add property creates an optional field; its editor opens at full content width below that heading. Values on this page are defaults for later additions. Card panels display stored keys only. Schema sections use the same vertical label drag and empty slot both within and between Default and Optional, including empty destinations. Drop updates order and membership in one undoable schema edit without changing any card; keyboard reorder and the context-menu move remain available. Property names and simple values edit inline; complex values and type settings use the shared anchored popups. Renaming a property changes its readable file key and affected card keys as one undoable action.


## View blocks

Shared Markdown view blocks use the same UI in cards and tag pages. Put a quiet Query summary above named view tabs; label it All views. Keep current-view Filter, Sort and View options on the tab toolbar, with readable filter chips immediately below. Conditions are compact property/comparison/value rows. Reveal Match all/any only for multiple conditions and nested groups only on request. Both levels use the same editor with explicit scope. Reuse existing menus, property controls and Status colors; view-tab drag reordering remains a follow-up. Multiple same-layout views are valid. Results reference source cards. Visible properties edit through the same controls as Card View; the title opens the source. See [View blocks](view-blocks.md) for the file format, editable-results contract and remaining implementation boundaries.


## Feature settings

Settings uses a two-column modal: a searchable feature sidebar and one scrolling settings page. Pages are General, Appearance, Navigation, Tags, Views and queries, Performance, and Developer. Keep the sidebar stable while content scrolls. Each setting has its name and short optional description on the left, and the control on the right; quiet separators divide rows. Use the existing pill toggle for Boolean settings, native selects for short enumerations, and theme surface/text tokens throughout. Keyboard users can move between feature tabs with arrows; Esc and outside click close the modal, with Tab kept inside it. Diagnostics belong only in Developer. Hardware acceleration remains device-wide, while query/property picker preferences are workspace-owned.

View-filter groups place Remove group at the top right of their own header. Removal actions use the shared danger hover/focus style. Nested groups keep a thin indentation guide rather than repeated heavy boxes. See [view blocks](view-blocks.md) for the implemented query and missing-value contract.


## Compact contextual menus

Follow the compact Notion-style direction in [Menus and tooltips](interactions/menus-and-tooltips.md#compact-menu-direction): approximately 290 px for setup menus, one setting per row, 13 px text, 16 px icons, restrained dividers and explicit theme tokens. Anchor to the clicked control, flip near edges and scroll long content internally. Window coordinates are only for placement constraints. Filter/YAML editors may be wider according to their content; never give all popups one large fixed width.

View options separates Layout, Properties and Group into focused subpanels in the same anchored surface, with Back returning to the parent menu. ## Card popups and tab navigation

Kanban card clicks open a centered editable Card popup over a dimmed background. Keep the source view mounted, with its selected view and scroll position intact. Reuse Card View’s title, tags, properties, Markdown editor, file writes and undo history. Clicks inside a property edit that value; pointer movement beyond the shared drag threshold moves the card without opening it. Whiteboard card menus and full-card toolbar menus can open this same popup.

Use a compact toolbar with Open in same tab, Open in new tab, the editable filename, formatting, More and Close. More also offers another Tab Group. Escape and backdrop clicks close the popup; nested menus consume Escape first. Save before closing or transferring to a tab. A failed save retains the popup and draft with a visible error. Use the theme surface, 12px corners, a restrained shadow and a maximum width of 920px. Native modal focus containment includes nested property menus and tag suggestions.

Back/Forward sit immediately to the right of the path. Each tab owns its navigation history; switching tabs does not record a visit. Following a card link or opening in the same tab records a visit, and navigating after Back truncates only that tab’s forward entries. Explicit Open in new tab creates a separate tab in the current Tab Group. Ordinary Explorer reopening can focus an existing tab. Moving a tab carries its history; renaming a folder updates its history paths. Disabled navigation buttons retain their position. History is bounded to 100 visits per tab and stored with workspace layout preferences, outside note files.

Destructive menu items use `--negative` for both text and icon on hover or keyboard focus. Do not introduce an undefined danger color or override the shared theme color in individual menus.
